# 三维与体数据验收记录

日期：2026-09-19。API 与支持范围见 [三维与体数据](科学绘图三维与体数据.md)，
任务勾选见 [科学绘图 TODO](科学绘图TODO.md)。

## 环境与结果

- Windows 11 x64，系统版本 10.0.26200。
- Intel Core i7-12650H；系统枚举的显示设备包含 NVIDIA GeForce RTX 4060 Laptop GPU，驱动 32.0.16.1088。
- MinGW-w64 GCC 15.2.0，C++17，Release。项目编译选项以 `-Os` 覆盖 CMake 默认的 `-O3`。
- OpenGL + GLFW 与 OpenGL + SDL2（2.32.10）使用独立构建目录、真实窗口和有效桌面。
- 两套配置分别通过全部 18 个 `^plot_` CTest，包括二维数值/图形/矢量/轮廓回归、三维数值、
  五个窗口 probe、导出，以及二维和三维基准。两个阶段集成示例在两套配置下均编译通过。
- `EUI_ENABLE_PLOT=OFF` + bundled 离线配置通过；生成目标和 CTest 中不包含 plot 模块、新示例或 plot 测试。
- 新增数值实现通过 GCC `-Wall -Wextra -Wpedantic -fsyntax-only` 检查。

窗口 probe 验证 1×/2× DPI、Runtime 轨道旋转/平移/缩放/选择/测距、拖动捕获与外部释放、
交互中重组、禁用、静置、体数据版本更新。它将切片、等值面和体积分结果上传后全图读回，与 CPU
参考像素逐字节比较；检查 viewport、depth/cull/scissor 状态及 unpack 参数恢复。
同尺寸纹理复用，32 次创建/释放后等待 GL 完成并断言 texture 已删除。

GPU 加速补充验证：`plot_spatial_runtime_probe` 在非默认 GL 状态下运行 GPU 求交，检查状态恢复、
深度、相机更新不重传 BVH、同尺寸纹理复用及释放。解析切片和等值面读回与 CPU 相同，体绘制
最大通道误差为 1（RGBA8）。两个 gallery probe 直接复用示例场景，在正交/透视下逐面板对照；
96×72 的 28 张图中，仅第三阶段透明相交的透视图有 3 个像素通道差异超过 4，其余均不超过 4。
测试允许小于 1% 的边界像素差异，同时约束全图平均通道误差低于 0.8，不能解释为任意场景精确相等。

高分辨率输出测试使用 1200×900、192 DPI 与 2× 文本倍率，执行 PNG/SVG/PDF 写出；PNG 解码测试
断言图层位置和透明度混合的实际像素。SVG 检查嵌入 PNG 与 text，PDF 检查 image XObject、
soft mask、字体资源及转义。这里没有把窗口截图当作矢量输出。

## 资源预算与性能

CPU 基准预算：16 MiB 三维工作空间、1 MiB 体缓存；窗口使用模块默认 64 MiB 输出纹理预算。
预算超限不要求降级显示，而要求报告容量错误。默认更大的 128 MiB 工作预算见 API 文档。
基准采用 25³ 高斯体、160×120 像素，独立进程串行执行，预热 2 次后记录 8 次固定旋转。
原始机器可读数据保存在 [plot-spatial-baseline.json](plot-spatial-baseline.json)。

| 场景 | 世界步长 | CPU 中位数 ms | CPU P95/P99 ms | 末帧体样本数 |
| --- | ---: | ---: | ---: | ---: |
| 体积分 | 0.16 | 25.19 | 25.84 | 见 JSON |
| 体积分 | 0.08 | 32.39 | 33.33 | 见 JSON |
| 体积分 | 0.04 | 46.71 | 47.47 | 见 JSON |
| 切片 | — | 22.02 | 22.71 | 0 |
| 等值面 | — | 29.37 | 30.16 | 0 |

八次测量的 P95/P99 均采用最大样本，只用于本机比较，不能推断稳定长尾分布或高分辨率帧率。
这些时间是 CPU 射线渲染耗时，未包含建模/等值面提取、字体、PNG 编码、GL 上传和窗口呈现。
旧 CPU 基准未采集的 GPU 时间和进程 GPU 占用在 JSON 中为 null。

### Gallery 交互加速补充

原先 `compose()` 同步 CPU 逐像素求交，2× 使像素数增加到四倍。现在视口使用 OpenGL 3.3
GPU BVH 求交和体积分，复用几何、体纹理、输出纹理与标签；CPU 保留拾取和导出。
图元共边加入浮点容差，避免切片网格出现裂缝；细线求交用最近点形式避免相减损失精度。

以下为 GLFW、1680×980 逻辑布局、所有面板放大 2.5 倍、一次预热后 12 次旋转的结果。
墙钟时间包括 compose 并等待 glFinish；GPU 时间来自 GL_TIME_ELAPSED。单面板列是逐个面板进行
5 次缩放后，最慢面板的中位数，包含整页 compose 和 GPU 完成等待。

| Gallery | DPI | 全部重绘中位数 ms | 最大样本 ms | GPU 中位数 ms | 单面板缩放中位数 ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| 第三阶段，6 面板 | 1× | 4.68 | 4.96 | 4.28 | 2.62 |
| 第三阶段，6 面板 | 2× | 24.67 | 25.37 | 24.11 | 6.00 |
| 第四阶段，8 面板 | 1× | 7.33 | 7.78 | 6.25 | 4.05 |
| 第四阶段，8 面板 | 2× | 17.43 | 75.38 | 15.92 | 8.73 |

同进程还记录缩放结束（约 2.63 倍）后、同尺寸全部面板的单次 CPU 参考渲染：第三阶段约
2.94 / 11.88 秒，第四阶段约 4.04 / 15.91 秒（1× / 2×）。CPU 样本不是稳定分位数，
与 GPU 旋转测量的相机姿态也不同，不能用其计算精确速度倍率。
原始数据见 [plot-gallery-gpu-baseline.json](plot-gallery-gpu-baseline.json)。
测量不包含 present，不等于屏幕帧率；2× 第四阶段仍观察到一次 75 ms 全部重绘长帧。
没有通过降低 DPI、固定小纹理或减少体采样步数获得这些结果。超 GPU 预算/精度范围时的 CPU
回退、大体数据首次上传、CPU 等值面重建及离线导出仍可能耗时。

512³ Float64 数据源的逻辑体积为 1,073,741,824 字节。128 处稀疏三线性查询产生 153 次块加载，
缓存记账峰值 1,019,032 字节，低于 1 MiB；`clearCache()` 后为零。该测试证明按需数据路径不默认
分配完整数组，不证明对整个 512³ 体提取等值面或高分辨率体绘制具有实时性能。

输入数据、应用持有的额外结果、字体缓存、GL 退休中的旧纹理和分配器元数据不属于上述工作预算。
当前没有进程 Private Bytes/Working Set/共享显存/专用显存/句柄的长期压力报告；不能把
缓存归零或单个纹理删除推广为全进程无泄漏。对应贯穿阶段验收项继续未勾选。

## 复现命令

构建命令见 API 文档。全量绘图回归：

```powershell
ctest --test-dir build -R '^plot_' --output-on-failure
ctest --test-dir build-sdl2 -R '^plot_' --output-on-failure
```

独立性能场景（在完成构建后串行执行）：

```powershell
./build/plot_spatial_benchmark.exe 0.16 volume
./build/plot_spatial_benchmark.exe 0.08 volume
./build/plot_spatial_benchmark.exe 0.04 volume
./build/plot_spatial_benchmark.exe 0.08 slice
./build/plot_spatial_benchmark.exe 0.08 isosurface
./build/plot_gallery_phase3_probe.exe
./build/plot_gallery_phase4_probe.exe
```

可加第四个命令行参数作为 PNG 路径以保存最后一帧，例如：
`./build/plot_spatial_benchmark.exe 0.08 volume build/volume.png`。
数值/窗口测试失败时返回非零状态，CTest 保留日志；完整随机操作序列与失败截图自动归档仍属于
贯穿阶段待办。未验证 Linux、macOS、Vulkan 视口及其他 GPU 驱动。

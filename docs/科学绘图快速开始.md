# 科学绘图快速开始

本文带你从仓库构建一个最小绘图应用。完整 API、线程规则和数据边界见
[科学绘图](科学绘图.md)；采集线程、波形缓冲和窗口关闭顺序见
[科学绘图应用开发](科学绘图应用开发.md)。

## 构建仓库内最小示例

需要 CMake、C++17 编译器和当前平台可用的 OpenGL 桌面环境。OpenGL 是推荐的交互后端：
二维使用 GPU 绘图，三维通常使用 GPU BVH/体绘制；超出预算、尺寸或精度范围时可能回退 CPU。

```powershell
cmake -S . -B build-plot `
    -DEUI_DEPS_MODE=bundled `
  -DEUI_ENABLE_MODULES=ON `
  -DEUI_ENABLE_PLOT=ON `
  -DEUI_RENDER_BACKEND=opengl `
  -DEUI_BUILD_APPS=ON
cmake --build build-plot --config Release --target scientific_plot_minimal --parallel 6
```

Visual Studio 多配置生成器的程序位于 `build-plot/Release/scientific_plot_minimal.exe`；
单配置生成器通常位于 `build-plot/scientific_plot_minimal`（Windows 上带 `.exe` 后缀）。窗口启动、窗口尺寸、DPI 和输入分发
由 EUI 应用入口处理，不需要手写渲染循环。示例源码见
[`scientific_plot_minimal.cpp`](../examples/scientific_plot_minimal.cpp)。

## 接入自己的应用

源码子目录接入时，需在 `add_subdirectory()` 前启用模块；不要用 `FORCE` 覆盖宿主项目已有的
CMake cache 选择：

```cmake
set(EUI_ENABLE_MODULES ON CACHE BOOL "Build EUI-NEO optional modules")
set(EUI_ENABLE_PLOT ON CACHE BOOL "Build the scientific plotting module")
add_subdirectory(path/to/EUI-NEO)

add_executable(my_app main.cpp)
target_link_libraries(my_app PRIVATE eui::module_plot)
```

也可在配置宿主项目时传入 `-DEUI_ENABLE_MODULES=ON -DEUI_ENABLE_PLOT=ON`。顶层直接构建
EUI-NEO 时模块发现默认开启；作为子目录依赖时默认关闭。安装包项目使用
`find_package(EuiNeo CONFIG REQUIRED)` 后链接同一个 `eui::module_plot` target。

典型代码在所属窗口的 `compose()` 中调用 `plot.compose()`，并在窗口设备销毁前释放图表资源：

```cpp
#include "eui_neo.h"
#include "modules/plot/plot.h"
#include "modules/plot/session.h"

namespace app {
namespace {
modules::plot::PlotSession plots;
auto plot = plots.make<modules::plot::Plot>();
} // namespace

const DslAppConfig& dslAppConfig() {
    static const auto config = DslAppConfig{}.onShutdown(plots.shutdownHandler());
    return config;
}

void compose(eui::Ui& ui, const eui::Screen& screen) {
    if (plot->series().empty()) {
        modules::plot::Series series;
        series.name = "Measurement";
        series.data = modules::plot::Data({0, 1, 2, 3}, {1, 3, 2, 4});
        plot->setSeries({series});
    }
    plot->compose(ui, "measurement", screen.width, screen.height, 1.0);
}
} // namespace app
```

在实际应用中，图表对象属于一个窗口的 UI 线程；后台线程只生成不可变数据，再通过应用的
异步机制或 `PlotSession::mailbox<T>()` 投递给 UI。多窗口分别创建 `PlotSession` 和图表。
示例中的 `dpi=1.0` 是基准倍率；高 DPI 窗口应传入当前窗口的实际 DPI scale。
完整停止采集、join 线程及 GPU 释放顺序见[应用开发指南](科学绘图应用开发.md#图表和生命周期)。

## 后端选择

| 后端 | 二维视口 | 三维/体数据视口 | 适用边界 |
| --- | --- | --- | --- |
| OpenGL | GPU 绘图 | GPU BVH 与体光线投射为主 | 推荐的交互路径；超预算、尺寸或精度限制时三维可回退 CPU；已在 GLFW、SDL2 验证 |
| Vulkan | CPU 光栅化后上传 | CPU 参考渲染后上传 | 视口可用但不走 GPU 绘图加速；Windows Vulkan probe 与 plot 回归已验证 |

Vulkan 拖动时二维视口临时以二分之一分辨率、三维视口以四分之一分辨率预览，松开后恢复完整
分辨率重绘。它改善交互反馈，但大型体数据的释放重绘仍可能较慢。Vulkan 当前没有 Linux、macOS
或多种 GPU/驱动覆盖，不应将单机基准当作帧率保证。最新后端和性能限制见
[模块 README](../modules/plot/README.md)。

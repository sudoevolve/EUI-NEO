# 科学绘图应用开发

本指南描述可直接使用的接口。完整应用模板见
[`scientific_plot_acquisition.cpp`](../examples/scientific_plot_acquisition.cpp)：独立窗口、双路 Int16
模拟采集、暂停检查、恢复跟随、原始值查询、可交互热力图及正确的退出顺序。
窗口、DPI、输入分发、清屏由正常的 EUI 应用入口处理，不要复制性能探针的手写帧循环。
初次接入可先读完整的最小窗口示例
[`scientific_plot_minimal.cpp`](../examples/scientific_plot_minimal.cpp)，目标名为 `scientific_plot_minimal`。

## 构建并运行

```powershell
cmake -S . -B build
cmake --build build --target scientific_plot_acquisition --parallel 6
./build/scientific_plot_acquisition.exe
```

外部项目链接 `eui::module_plot`；可通过 `add_subdirectory` 或安装包的 `find_package(EuiNeo)`
接入。此模块的图形后端目前为 OpenGL。完整外部构建入口见[科学绘图](科学绘图.md)。

## 图表和生命周期

在所属窗口的 UI 线程创建一个 `PlotSession`，通过 `make<T>()` 管理 `Plot`、`HeatmapPlot`、
`PolarPlot`、`Figure` 或 `Plot3D`。将它的关闭处理器注册到**同一窗口**的设备销毁前回调：

```cpp
#include "modules/plot/plot.h"
#include "modules/plot/session.h"

modules::plot::PlotSession charts;
auto plot = charts.make<modules::plot::Plot>();

// 在 dslAppConfig() 中：
config.onShutdown(charts.shutdownHandler());
```

应用有采集线程时，传入停止与 join 函数：

```cpp
config.onShutdown(charts.shutdownHandler([&] {
    stopping = true;
    if (worker.joinable()) worker.join();
}));
```

处理器按顺序关闭邮箱、调用停止函数、释放全部托管图表的 GPU 资源；重复调用无副作用。
停止函数不得抛异常，设备读取应有超时/取消机制，不能永久阻塞 `join()`。
Session 的创建、`make()`、注册与执行关闭回调必须在同一 UI 线程；错误线程会抛出异常。

这是显式接入窗口生命周期的管理器，不是任意线程可析构的 GPU 包装器。不要在窗口设备销毁
后才调用关闭处理器。关闭后的共享图表引用不能再次用于绘制；多窗口不能共用一个 Session。
主应用直接使用 `DslAppConfig::onShutdown`；自定义子窗口需接入其自身的设备销毁前回调。

## 后台数据到 UI

`LatestValue<T>` 是有容量上限的**显示结果邮箱**，只保存最新的一份值。它不替代原始历史或
文件记录。生产者生成完整不可变数据后发布，UI 在显示节奏中取走；没有无界的逐包 UI 任务队列。

```cpp
auto incoming = charts.mailbox<std::vector<modules::plot::Series>>();

// 采集/计算线程：仅操作数据，不触碰 Plot。
incoming->publish(std::move(series));

// compose 中的 UI 定时器：
ui.stack("plot.page")
  .onTimer(1.f / 60, [incoming, plot] {
      if (auto next = incoming->take()) plot->setSeries(std::move(*next));
  })
  .content([&] { plot->compose(ui, "plot", width, height, dpi); })
  .build();
```

邮箱本身不会唤醒窗口，所以示例使用 `onTimer` 定期取结果；静态图表不需要定时器。
`publish()` 返回 `false` 表示窗口正在退出，此时生产者应结束。丢弃被替代的显示快照不代表
丢弃采集数据；要保留所有原始样本，使用历史缓冲并处理它的背压。
普通离线分析亦可使用框架现有 `app::async::runOnce/restart`，在 UI 完成回调中更新图表。

## 波形配置与数据接入

默认 `WaveformBuffer::Config{}` 为双路 100 kS/s、1 秒历史、4,096 点块、64 MiB 预算；
固定池实际预留不到 1 MiB。小应用不会意外分配超过 1 GB。

```cpp
using namespace modules::plot;
auto config = WaveformBuffer::Config::forDuration(
    2, 200000, 1.0, SampleFormat::Int16); // 通道数、每路采样率、历史秒数
auto bytes = WaveformBuffer::requiredBytes(config); // 分配前查询
auto buffer = std::make_shared<WaveformBuffer>(config);
```

`forDuration()` 根据采样率选取 256～65,536 点块，并预留至少约 100 ms 的快照重叠备用空间，
历史向上取整到完整块；预算不足会在分配前
报错。需要调整备用块数时修改返回的 Config，再次调用 `requiredBytes()` 检查。
原来的双路 125 MS/s、5 秒 UInt8 场景使用显式 `Config::dual125MS()`；其约 1.37 GB 固定池
是原始历史、备用块和索引的代价，不应作为所有应用的默认值。

| 输入 | 紧凑历史 | 数据含义 |
|---|---|---|
| `UInt8` | 每样本 1 字节 | 0～255 |
| `Int16` | 每样本 2 字节 | −32768～32767 |
| `UInt16` | 每样本 2 字节 | 0～65535 |
| double XY、NaN、非等间距 X | 使用 `Data(x,y)` | 无需量化到整数，但不是同等内存/吞吐路径 |

多通道按采样帧交错排列：`ch0(t0), ch1(t0), ch0(t1), ch1(t1), ...`。
16 位输入使用本机字节序，不要直接传入字节序不同的设备协议帧。
当前紧凑流式缓冲不支持浮点格式、不连续时间戳或自动插入丢包缺口；不要把它们静默转换为
整数或连续采样。普通 `Data` 仍支持浮点数据及 NaN 断线。

设备恰好返回一个完整块时，调用 `buffer->tryAppend(pointer, buffer->blockBytes())`；
返回 false 表示整块未接收。设备包长不固定时，使用 `WaveformInput`：

```cpp
WaveformInput input(buffer); // 一个采集生产者持有一个适配器
std::size_t accepted = input.write(packet.data(), packet.size()); // 字节数
// accepted < packet.size()：保留剩余后缀，在空间可用时重试，不能直接丢弃。
```

适配器支持半个采样、跨块及多块包；完整块可直接进入历史，尾部只暂存一块。
返回的已接收前缀可能仍在暂存区，只有完整块才对快照可见。结束时检查 `pendingBytes()`：
`flush()` 可重试被背压阻塞的完整块，但不会为未完成的块补零、虚构样本。不得同时用其他
生产者或 `tryAppend()` 向同一个适配器正在使用的缓冲穿插写入。

```cpp
auto snapshot = buffer->snapshot();
Series first, second;
first.data = snapshot.channels[0];
second.data = snapshot.channels[1];
plot->setSeries({first, second}); // UI 线程
```

X 为绝对采样时间（秒），Y 保留原始整数值；显示按视口自动查询峰值，无需应用自行降采样。
`snapshot.firstSample + pick.index` 是采集序号。旧快照会固定其引用的数据块，备用块耗尽时
返回背压，不覆盖旧数据。冻结整个五秒历史同时长期持续采集，必须增加预算、暂停采集，或
将冻结部分复制到独立记录；示例采用暂停采集策略。
UI 消费过慢而触发背压时，生产者也需要继续发布已接收数据的最新快照，让 UI 有机会释放
旧快照；不能等下一个块成功写入才再发布，否则可能相互等待。独立示例包含这个分支。

## 热力图交互与原始值

```cpp
auto heatmap = charts.make<HeatmapPlot>();
heatmap->setField(ScalarField(rows, columns, std::move(values), {0, 10}, {-5, 5}));
heatmap->compose(ui, "field", width, height, dpi);
if (auto p = heatmap->probe()) {
    // p->row、p->column、p->position、p->value 是原始数据样本。
}
```

左键拖动平移，滚轮以指针为中心缩放，Shift+拖动框选放大，右键复位。
支持 `setAxes/axes/resetView/pan/zoom/setEnabled`；坐标轴保留手动范围，因此更新场数据不会
抹掉用户的缩放。轴支持线性、反向和对数；对数轴跨零场的自动显示下限为正上限的百万分之一
（至少 double 的最小正正规值），需要特定正区间时显式设置范围。

`CellCenters` 返回指针所在单元的原始值；`GridPoints` 返回最近原始顶点，**不是**绘制色块的
四顶点平均值。NaN 可以作为原始值返回；图外返回空。独立数值查询使用 `pickField(field,point)`。
缩放只改变坐标，不改变色阶范围；颜色映射继续由 `ColorScale` 控制。热力图现在有交互，
但并不因此宣称 PolarPlot、三维图与二维图全部共享同一种交互或 Figure 联动机制。

## 开发写法是否简单

普通图表只需要“建图、设置数据、compose、注册一次关闭处理器”。后台更新再增加“邮箱发布、
UI 定时取值”，无需手写 OpenGL、鼠标捕获、图表资源列表或逐点显示降采样。
独立示例的额外代码主要是模拟设备、取消与背压，以及操作栏。真实设备的驱动、错误恢复、
协议解码依旧由应用负责，不能用几行绘图代码代替完整采集应用。

## 验证与性能边界

`plot_application` 验证轻量预算、UInt8/Int16/UInt16、奇数字节分包、背压重试、邮箱与关闭顺序、
热力图裁剪和原始值；`plot_application_probe` 在真实 OpenGL 窗口中验证 1×/2× 拖拽、滚轮、
禁用、复位、重组和资源关闭。既有 `plot_waveform` 覆盖历史回绕和并发快照。
`plot_acquisition_flow` 直接运行独立示例的采集逻辑，验证慢 UI 下跨越多轮历史回绕、暂停后
保留手动视图、恢复采集以及重复关闭。
本次 Windows/OpenGL 验证：GLFW 22 项绘图回归通过，SDL2 23 项通过（多一项吞吐探针的默认
数值自检，不代表完整吞吐测试）。安装到独立目录后，`find_package(EuiNeo)` 消费项目的
`eui_find_package_plot` 亦通过，覆盖新 Session、邮箱和轻量缓冲接口。
原吞吐历史数据见[二维波形高吞吐优化](二维波形高吞吐优化.md)；更换格式、线程策略或预览
渲染循环后，不应直接复用历史 FPS 数字。独立示例是接入模板，不是 250 MB/s 压力测试。

新增接口后的 SDL2/OpenGL 高速回归使用 `plot_throughput_probe --production`，同一 i7-12650H /
RTX 4060 Laptop、1920×1080、双路 UInt8、5 秒历史、约 65,536 点视口：

| 倍率 | 接收 MB/s | 显示帧/s | 帧中位数 | P99 | 超过 16.67 ms 的帧 |
|---|---:|---:|---:|---:|---:|
| 1× | 249.996 | 59.87 | 12.87 ms | 17.14 ms | 4 / 311 |
| 2× | 250.001 | 59.86 | 13.71 ms | 17.49 ms | 7 / 311 |

两次各接收全部计划的 2,550,005,760 字节，无池背压；各自逐字节校验保留的 1,250,033,664
字节，错误为零。这次 P99 超过 16.67 ms，因此不能宣称每一帧均满足 60 Hz 帧预算。
这是合成重放和软件注入鼠标事件，允许生产者在调度延迟后追赶，不是设备 DMA 零丢失或硬件
鼠标端到端延迟保证。原始指标见 [plot-application-throughput.json](plot-application-throughput.json)。

# 集成指南

本文面向把 EUI-NEO 接入外部 C++ 项目的用户。先按唯一的“快速开始”创建完整桌面应用，再按需要查阅安装包、`FetchContent` 或自定义主循环：

- 完整应用：调用 `eui_neo_configure_app(target)`，由框架配置入口、链接和资源。
- 已有主循环：直接链接 `eui::neo`，自行接入窗口、输入和渲染。
- 安装包：先 `cmake --install` 或下载 Release SDK，再使用 `find_package(EuiNeo CONFIG REQUIRED)`。

EUI-NEO 通过 CMake 导出一个库 target：

```cmake
eui::neo
```

当 EUI-NEO 作为子目录接入时，默认不会构建仓库自带的示例或应用。需要构建 `examples/` 下的短小演示时，配置 `-DEUI_BUILD_APPS=ON`；需要构建 `apps/` 下的较长或多页面应用时，配置 `-DEUI_BUILD_USER_APPS=ON`。

## Xmake

Xmake 3.0+ 支持源码构建和 xrepo 接入。外部项目只需要声明包并链接目标：

```lua
set_languages("cxx17")
add_requires("eui-neo")

target("my_app")
    set_kind("binary")
    add_files("main.cpp", "app.cpp")
    add_packages("eui-neo")
```

直接构建仓库示例时，Debug 和 Release 分别使用独立配置命令：

```powershell
# Debug
xmake f -m debug -y --apps=y --user_apps=y
xmake build gallery

# Release
xmake f -m release -y --apps=y --user_apps=y
xmake build gallery
```

Windows 下对应的 EXE 路径是 `.xmake/build/windows/x64/debug/gallery.exe` 和
`.xmake/build/windows/x64/release/gallery.exe`。如果配置过自定义 `builddir`，将
`.xmake/build` 替换为该目录。Xmake 会保留已配置的 `apps`/`user_apps` 值；之前关闭过示例时，需要在 `xmake f` 中显式传入
`--apps=y --user_apps=y`。可用
`xmake show -l targets` 查看目标，再用 `xmake build shadertoy` 构建其他示例。

窗口后端、渲染后端和共享库选项分别使用 `--window_backend=sdl2`、
`--render_backend=vulkan` 和 `--shared=y`。源码树应用使用同一个 `eui.app` 规则
处理平台入口和运行资源，不需要引用 `core/app/`。

## 从 Quick Start 继续

完整的项目结构、`CMakeLists.txt`、`app.cpp` 和构建命令只在
[README 快速开始](../README.zh-CN.md#快速开始)维护一份。本指南记录它的可选路径。

默认使用 GLFW + OpenGL。需要 Vulkan 时使用独立构建目录：

```sh
cmake -S . -B build-vk -DCMAKE_BUILD_TYPE=Release
```

需要 SDL2 窗口后端时，只需选择后端：

```sh
cmake -S . -B build-sdl2 -DCMAKE_BUILD_TYPE=Release
cmake --build build-sdl2 --parallel
```

`eui_neo_configure_app(my_app)` 会加入当前选择的 app main、链接 `eui::neo`、设置平台可执行文件选项，并把 EUI-NEO 的 `assets/` 复制到可执行文件目录。外部项目不需要引用 `core/app/`。

Shadertoy graph、JSON、Vulkan SPIR-V helper 和双后端约束见
[Shadertoy 底层图元](Shadertoy.md)。

## 已有主循环

如果你已经有自己的 main、窗口系统、渲染 context 或事件循环，直接链接 EUI-NEO 导出的静态库 target：

```cmake
add_subdirectory(external/EUI-NEO)

add_executable(my_app main.cpp app.cpp)
target_link_libraries(my_app PRIVATE eui::neo)
eui_neo_copy_assets(my_app)
```

普通 UI 代码仍然优先包含公共 facade：

```cpp
#include "eui_neo.h"
```

只有接入边界需要包含底层 runtime / platform 头文件。比如嵌入已有 GLFW / OpenGL 主循环时，才会直接使用 `core::dsl::Runtime`。

也可以用 CMake `FetchContent` 拉取 EUI-NEO：

```cmake
include(FetchContent)

FetchContent_Declare(
    eui_neo
    GIT_REPOSITORY https://github.com/sudoevolve/EUI-NEO.git
    GIT_TAG        main
)
FetchContent_MakeAvailable(eui_neo)

add_executable(my_app main.cpp app.cpp)
target_link_libraries(my_app PRIVATE eui::neo)
eui_neo_copy_assets(my_app)
```

实际项目建议把 `GIT_TAG` 固定到 release tag 或具体 commit，避免上游变化影响构建复现。

## 安装包 / find_package

从源码安装：

```sh
cmake -S . -B build-install -DCMAKE_BUILD_TYPE=Release -DEUI_BUILD_APPS=OFF
cmake --build build-install --parallel
cmake --install build-install --prefix /tmp/eui-install
```

外部项目：

```cmake
cmake_minimum_required(VERSION 3.14)
project(MyProject LANGUAGES CXX)

find_package(EuiNeo CONFIG REQUIRED)

add_executable(my_app app.cpp)
eui_neo_configure_app(my_app)
```

配置外部项目：

```sh
cmake -S . -B build -DCMAKE_PREFIX_PATH=/tmp/eui-install
cmake --build build --parallel
```

安装包会提供 `eui::neo`、所选窗口后端的应用入口和完整运行资源；`eui_neo_configure_app()` 的写法与源码子目录接入一致。SDL2 / Vulkan 配置仍需要消费方环境提供对应 SDK 或包。

## Release SDK

从 GitHub Releases 下载与平台、架构匹配的 `*-sdk.zip` 或 `*-sdk.tar.gz`，解压到固定目录。SDK 已包含头文件、库、CMake 配置文件和运行资源，不需要把仓库源码放进外部项目。

Linux / macOS：

```sh
mkdir -p "$HOME/opt/eui-neo"
tar -xzf EUI-NEO-*-sdk.tar.gz -C "$HOME/opt/eui-neo"
cmake -S . -B build -DCMAKE_PREFIX_PATH="$HOME/opt/eui-neo"
cmake --build build --parallel
```

Windows PowerShell：

```powershell
Expand-Archive .\EUI-NEO-*-sdk.zip -DestinationPath "$env:LOCALAPPDATA\EUI-NEO"
cmake -S . -B build -DCMAKE_PREFIX_PATH="$env:LOCALAPPDATA\EUI-NEO"
cmake --build build --config Release --parallel
```

项目中的 `CMakeLists.txt` 使用 `find_package(EuiNeo CONFIG REQUIRED)` 和 `eui_neo_configure_app(my_app)`，运行时资源由 SDK 配置自动部署。SDL2 / Vulkan 仍需安装对应的消费方开发包或 SDK。

## 仓库内示例开发

快速实验、复现问题或新增内置 demo 时，可以直接在仓库的 `examples/` 下开发：

```text
examples/
  eui_demo.cpp
  animated_card.cpp
  my_app.cpp

apps/
  gallery/app.cpp
  calculator/app.cpp
  serial_tool/app.cpp
```

`examples/my_app.cpp`：

```cpp
#include "eui_neo.h"

namespace app {

const DslAppConfig& dslAppConfig() {
    static const DslAppConfig config = DslAppConfig{}
        .title("My EUI App")
        .pageId("my_app")
        .windowSize(900, 600)
        .fps(90.0);
    return config;
}

void compose(eui::Ui& ui, const eui::Screen& screen) {
    ui.column("root")
        .size(screen.width, screen.height)
        .padding(32.0f)
        .gap(12.0f)
        .content([&] {
            ui.text("title")
                .text("Hello EUI-NEO")
                .fontSize(28.0f)
                .lineHeight(36.0f)
                .build();

            components::button(ui, "button")
                .text("Click")
                .onClick([] {
                    // update your app state here
                })
                .build();
        })
        .build();
}

} // namespace app
```

顶层构建会自动扫描 `examples/*.cpp`，并为每个文件生成同名可执行程序：

```sh
cmake -S . -B build
cmake --build build
./build/my_app
```

复杂应用应放到 `apps/<name>/`：应用入口使用 `app.cpp`，多页面内容拆到 `pages/*.h`，应用专属组件拆到 `components/`，资源放到 `assets/`。例如 `apps/gallery/` 只保留应用入口、全局主题、导航壳和页面路由；具体页面放在 `apps/gallery/pages/*.h`。每个页面文件定义一个页面对象，例如 `GalleryControlsPage`，对象内部持有自己的交互状态，并提供 `compose(eui::Ui&, float width, float height)` 声明页面内容。这种方式接近 QML 的页面组件模型：入口负责装配和切换，页面自己管理自己的状态和画面。

```text
apps/
  gallery/
    app.cpp                # app shell, route, shared theme
    pages/
      gallery_controls.h   # struct GalleryControlsPage { state + compose(...) }
      gallery_bing.h
      gallery_about.h
```

`apps/gallery/pages/*.h` 是被 `apps/gallery/app.cpp` 包含的页面组件头，不是独立编译单元。页面里可以直接使用 `app.cpp` 中的主题 token、动画 helper 和共享小工具；业务交互状态优先放在页面对象里，而不是继续堆在入口文件的匿名 namespace。

因此使用 VSCode 的 Microsoft C/C++ 扩展单独打开 `apps/gallery/pages/*.h` 时，可能会因为看不到 `app.cpp` 中的主题 token、动画 helper 或共享函数而出现红线。这是 IntelliSense 上下文限制，不代表真实构建失败。建议以 CMake 构建结果为准；如果希望减少这类误报，可以改用 clangd，或直接忽略 `apps/gallery/pages` 下的 Microsoft C/C++ 红线。

测试 SDL2 后端时，单独开一个构建目录：

```sh
cmake -S . -B build-sdl2
cmake --build build-sdl2 --target serial_tool
./build-sdl2/serial_tool
```

## 嵌入已有 GLFW / OpenGL 主循环

如果你的程序已经自己创建了 GLFW 窗口和 OpenGL context，可以直接持有一个 `core::dsl::Runtime`：

```cpp
#include "core/dsl_runtime.h"
#include "core/input/input_state.h"

core::dsl::Runtime runtime;
runtime.initialize(window);

while (!glfwWindowShouldClose(window)) {
    glfwPollEvents();

    int framebufferWidth = 0;
    int framebufferHeight = 0;
    glfwGetFramebufferSize(window, &framebufferWidth, &framebufferHeight);

    float contentScaleX = 1.0f;
    float contentScaleY = 1.0f;
    glfwGetWindowContentScale(window, &contentScaleX, &contentScaleY);
    const float dpiScale = (contentScaleX + contentScaleY) * 0.5f;
    const float logicalWidth = static_cast<float>(framebufferWidth) / dpiScale;
    const float logicalHeight = static_cast<float>(framebufferHeight) / dpiScale;

    runtime.compose("embedded", logicalWidth, logicalHeight, [](eui::Ui& ui, const eui::Screen& screen) {
        ui.row("root")
            .size(screen.width, screen.height)
            .content([&] {
                ui.text("hello")
                    .text("Embedded EUI-NEO")
                    .position(24.0f, 24.0f)
                    .fontSize(22.0f)
                    .build();
            })
            .build();
    });

    const bool shouldRender = runtime.update(window, deltaSeconds, dpiScale, dpiScale, true);
    if (shouldRender) {
        runtime.render(framebufferWidth, framebufferHeight, dpiScale);
        glfwSwapBuffers(window);
    }
}

runtime.shutdown();
```

SDL2 custom loops must route each native event by `windowID` and submit it before calling
`Runtime::update`:

```cpp
switch (event.type) {
case SDL_MOUSEMOTION:
    core::queuePointerMotion(targetWindow,
                             event.motion.x,
                             event.motion.y,
                             (event.motion.state & SDL_BUTTON_LMASK) != 0,
                             (event.motion.state & SDL_BUTTON_RMASK) != 0);
    break;
case SDL_MOUSEBUTTONDOWN:
case SDL_MOUSEBUTTONUP:
    core::queuePointerButton(targetWindow,
                             event.button.x,
                             event.button.y,
                             event.button.button == SDL_BUTTON_RIGHT ? 1 : 0,
                             event.type == SDL_MOUSEBUTTONDOWN);
    break;
case SDL_TEXTINPUT:
    core::queueTextInput(targetWindow, event.text.text);
    break;
case SDL_MOUSEWHEEL:
    core::queueScrollInput(targetWindow, event.wheel.preciseX, event.wheel.preciseY);
    break;
default:
    break;
}
```

Use `queueTextEditing()` for `SDL_TEXTEDITING`, `queueKeyInput()` for supported `SDL_KEYDOWN`, and
`queuePointerPresence()` for pointer enter/leave. Clear pointer state with
`clearPointerInput()` when a window is hidden, minimized or closed. The bundled SDL2 entry
point contains the complete reference mapping.

嵌入模式下，你需要自己负责：

- `glfwInit()` / `glfwTerminate()`。
- 创建 OpenGL 3.3 core profile context。
- 调用 `gladLoadGLLoader(...)`。
- 安装或转发输入事件。直接使用 EUI-NEO 的 `core/input/input_state.h` 时，可调用 `core::installInputCallbacks(window)`。
- 主循环节流、清屏、swap buffers 和窗口生命周期。

如果不需要完全自定义主循环，优先使用“公共头文件方式”。

Vulkan 安装包还导出 `eui::shadertoy_wrap`、`eui_compile_shadertoy()`、
`eui_compile_shadertoy_inline()` 和 `eui_compile_shadertoy_config()`。外部应用在
`find_package(EuiNeo CONFIG REQUIRED)` 后可直接调用 helper，也可提供预生成 SPIR-V。
其中 `eui_compile_shadertoy_config()` 接收一个 Shadertoy JSON，自动发现其中的全部
Pass，读取每个 Pass 的 `source`、`inlineSource`、`spirv` 和 `uniforms`，并为 Vulkan
生成对应的 SPIR-V；构建系统无需再维护 Pass 数量或按下标覆盖路径：

```cmake
eui_compile_shadertoy_config(my_app
    CONFIG "${CMAKE_CURRENT_SOURCE_DIR}/shaders/effect/config.json"
    ASSET_ROOT "${CMAKE_CURRENT_SOURCE_DIR}/shaders"
    OUTPUT_ROOT "${CMAKE_CURRENT_BINARY_DIR}/assets/shaders")
```

`OUTPUT_ROOT` 必须对应运行时资源树中的 `ASSET_ROOT`。只有实际生成 SPIR-V 的构建机需要
Vulkan SDK `glslangValidator` 和 Python 3；目标机只需要 Vulkan loader/driver 和产物。
OpenGL 安装包不会安装或探测这些 Vulkan 构建工具。

## 依赖和资源

EUI-NEO 的第三方依赖由 `3rd/dependencies.cmake` 处理：

- `EUI_DEPS_MODE=auto`：默认。GLFW / glad 依次尝试父项目已有 target、包管理器 target、本地 `3rd/` 和固定上游；SDL2 先查找系统包再拉取；其余 vendored 依赖优先使用本地 `3rd/`，缺失时从固定上游拉取。
- `EUI_DEPS_MODE=bundled`：严格离线，只使用 `3rd/`。
- `EUI_DEPS_MODE=fetch`：强制联网拉取。

`3rd/dependencies.cmake` 是 `3rd/` 顶层唯一由 EUI-NEO 维护的 CMake 文件。GLFW、glad、tray、FreeType、zlib、libpng 和 MD4C 会根据各自的标志头文件与核心源码自动识别，不依赖源码目录名和版本后缀。替换版本时直接把一个完整的上游源码文件夹放到 `3rd/` 的下一层即可，不需要修改配置；同一个库同时存在两个匹配目录时会明确报错，避免选错版本。各源码目录内部的 `CMakeLists.txt` 属于上游构建文件，仍需保留。

GLFW / glad 是主程序和 EUI-NEO 都可能直接接触的公共接口依赖。父项目如果已经提供了名为 `glfw` 或 `glad` 的 CMake target，EUI-NEO 会优先复用已有 target，不会再自动引入 `3rd/` 下的同名依赖；没有已有 target 时，才按 `find_package`、内置源码或 fetch 兜底继续解析。

作为子目录接入时，`EUI_ENABLE_INSTALL` 默认关闭，避免把父项目提供的公共依赖 target 混入 EUI-NEO 的安装导出；需要统一安装时由父项目显式开启并管理这些公共 target。

窗口后端默认是 GLFW。SDL2 是可选后端，不 vendored 到 `3rd/`：

- `cmake -S . -B build-sdl2`：优先使用系统 SDL2 包，找不到时下载固定版本 SDL2。
- `cmake -S . -B build-sdl2 -DEUI_DEPS_MODE=fetch`：下载固定版本 SDL2。
- `cmake -S . -B build-sdl2 -DEUI_DEPS_MODE=bundled`：直接报错。

内置和 fetch 下载的依赖默认按静态链接构建，包括 GLFW。Release 包不需要额外携带 GLFW DLL / dylib / so。只有使用系统 SDL2 包时，SDL2 仍可能按系统包提供的方式动态链接。

MD4C 默认开启，用于 `components::markdown(ui, id)` 解析 Markdown 文本。仓库默认 vendored 在 `3rd/md4c`，可通过 `-DEUI_ENABLE_MARKDOWN=OFF` 关闭；关闭后 Markdown 组件会退化为纯文本段落显示。

Markdown 组件会接入 MD4C 的 block/span/text 回调面，并用现有 DSL primitive 可视化 CommonMark 与启用的 MD4C 扩展：标题、段落、引用、列表、任务列表、分隔线、代码块、HTML block、表格、表格对齐、强调、加粗、链接/自动链接、图片、inline code、删除线、LaTeX math、wiki link、underline、inline HTML、entity、soft/hard break 等。当前组件不是浏览器内核：HTML/CSS 不会执行；inline code、链接、图片、math、wiki、HTML、删除线和下划线会在组件内部 line-box 排版中映射成可见文本、胶囊或装饰线，图片显示为占位文本。代码、引用、HTML block 和表格使用块级样式显示。

运行时资源默认按 `assets/...` 查找。`eui_neo_configure_app()` 和
`eui_neo_copy_assets()` 在源码/add_subdirectory 接入时复制完整 EUI `assets/` 树，因此
`assets/shaders/shadertoy/` 下的 preset 与 schema 也会一起复制，不会产生嵌套的
`shaders/shaders`。`eui::platform::resolveResourcePath("assets/...")` 会先检查当前工作目录，
再检查可执行文件旁的相对路径，因此下载后的 runtime 可以从任意工作目录启动。内置
Shadertoy 和 Gallery 的 Vulkan SPIR-V 会生成到随 runtime 打包的 assets 树；外部应用
使用 helper 生成的 SPIR-V 仍需按自己选择的输出路径部署。外部项目可以：

- 调用 `eui_neo_copy_assets(my_app)` 复制 EUI-NEO 自带资源。
- 在自己的构建系统中复制应用 JSON、fragment、图片和预生成 SPIR-V。
- 通过 `DslAppConfig::textFont(...)`、`iconFont(...)`、`iconPath(...)` 指向自己的资源。

`cmake --install` 会把完整框架 `assets/` 安装进 SDK，`eui_neo_configure_app()` 会把它们
部署到消费方可执行文件旁。应用自己的 JSON、fragment、图片和预生成 SPIR-V 仍由应用目标部署。Shadertoy JSON importer 复用已链接的
`eui::json`/yyjson，图片 channel 复用现有 image decoder，运行时不增加大型 parser、
Shader 编译器或媒体依赖，公共 API 也不暴露 GL/Vulkan 对象。

默认文本字体和图标字体找不到 assets 资源时会尝试平台系统字体兜底，避免普通文本在单 exe 漏带 assets 时整段不可见。FontAwesome 图标的 codepoint 仍依赖兼容的图标字体；需要图标稳定显示时，发布包应携带默认 `assets/` 或通过 `.iconFont(...)` 指向可用字体。

## 适合公开给用户的最小承诺

- C++17。
- CMake 3.14+。
- 默认 OpenGL 3.3 core profile，或显式选择 Vulkan 1.0+ 后端。
- GLFW 默认窗口输入，SDL2 为可选构建后端。
- 两个渲染配置共享同一 Shadertoy graph/JSON/source/fixed-sampling/pass 契约；Vulkan 构建时提供 SPIR-V，运行时不需要 Shader 编译器。
- `eui::neo` 是库 target；示例程序是可选目标。

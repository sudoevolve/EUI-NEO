## EUI-NEO v0.5.8

本次版本完善动态图像输入和双渲染后端能力。

### 主要更新

#### 动态纹理与图像流

- 新增线程安全、有界的 `eui::ImageStream`，生产线程提交帧，渲染线程消费最新帧。
- 新增 `RGBA8`、`BGRA8`、`NV12`、`I420` 和 `P010` 图像格式。
- 支持 BT.601、BT.709、BT.2020，以及 Full/Limited 色彩范围。
- OpenGL 与 Vulkan 均支持 NV12/I420/P010 原生多平面纹理上传和 GPU YUV 转 RGB。
- 后端不支持原生 YUV 格式时自动回退到 CPU RGBA8 转换，保持 API 和显示结果一致。
- 动态纹理支持尺寸、格式切换、更新失败回退和最新帧丢弃策略。
- 动态图像不会错误进入 retained layer 缓存，帧更新会正确触发局部重绘。

#### 渲染与性能

- 优化 retained image、文本损坏区域和 backdrop blur 的捕获与采样路径。
- 保留 OpenGL/Vulkan retained layer 缓存，连续尺寸变化时复用容量并延迟安全释放资源。
- Vulkan image shader、rounded-rect shader 和对应 SPIR-V 生成头同步更新。

#### 应用入口与构建

- 修复 GLFW 静态库缺少 Null 平台实现导致的 `_glfwConnectNull` 链接错误。
- 修复 MinGW 构建误传 MSVC `/TC` 等参数的问题，并补充 JetBrains MinGW `bfd-plugins` 兼容处理。
- 修复 macOS GLFW Cocoa 定时器、Objective-C 源文件编译模式和 ARC 设置，兼容 Apple Silicon 构建。
- macOS Vulkan 配置可通过 Homebrew 前缀自动发现 SDK，不需要写死机器路径或手动设置固定目录。
- Linux GLFW 补充 `librt` 链接，兼容仍将 `clock_gettime` 等符号放在 librt 中的旧版系统。

#### 文档与示例

- 新增中文《动态纹理与图像流》文档，说明帧格式、色彩转换、线程模型、回退路径和测试方法。
- 新增 `dynamic_texture` 格式验证示例。
- 新增可选 `ffmpeg_video_player` 示例，演示 FFmpeg 解码到 NV12 再提交 `ImageStream` 的完整链路。
- 更新 CMake、SDK 和运行资源集成说明。

### 升级说明

- 动态纹理 API 为新增能力，不改变现有静态图片 API。
- `ImageFrame` 提交后必须保持其平面缓冲区有效且不可修改，直到该帧不再被引用。
- YUV 帧应明确填写色彩空间和色彩范围；不确定时不要依赖默认值。
- FFmpeg 播放示例属于可选示例，不会成为核心库的运行时依赖。

### 验证

- `image_stream`：帧校验、容量限制、最新帧消费、RGBA/BGRA/YUV 转换。
- `image_stream_primitive`：原生动态纹理创建、格式切换、更新失败回退。
- `dirty_rects`：动态内容与局部重绘交互。
- Windows/MSVC：已完成 `eui_neo` OpenGL/GLFW 回归构建，桥接 C 文件按 C 编译且无 C7555 或 `_glfwConnectNull` 链接错误。
- Linux：已完成 GLFW 源文件、X11 链接项、`librt` 和托盘依赖的配置审计；运行验证需要目标机安装对应 X11 开发包。
- macOS：已完成 Cocoa/Objective-C、Homebrew Vulkan SDK 和 Apple Silicon 配置审计；运行验证需要 macOS/Xcode 环境。
- OpenGL/Vulkan 动态纹理示例和 SDL2/GLFW 组合仍应在各目标平台分别运行验证。

# 二维波形高吞吐优化

针对双路 UInt8、每路 125 MS/s（总输入 250 MB/s）、保留最近 5 秒、视口约 65,536 点的场景，
框架现在提供 `WaveformBuffer`。它用固定容量块池保存原始字节，并为每个块建立最小/最大位置
索引；UI 快照只复制共享指针，折线绘制和拾取继续使用原始 `Data`。

普通 `Plot` 也使用相同的数据摘要：自动范围不再逐点扫描，像素列显示会对有序 X 数据做范围
查询，鼠标拾取按摘要包围盒递归查找，拖拽和缩放不再重建全屏点桶。

## 已测结果

在 Windows 11、i7-12650H、RTX 4060 Laptop、1920×1080 OpenGL 上，
`plot_throughput_probe --production` 以 250 MB/s 重放 10.2 秒：

| DPI | 接收速率 | 帧中位数 | P95 | P99 | 丢失 |
|---|---:|---:|---:|---:|---:|
| 1× | 250.004 MB/s | 11.79 ms | 13.61 ms | 14.78 ms | 0 |
| 2× | 249.996 MB/s | 12.31 ms | 15.00 ms | 15.88 ms | 0 |

两种 DPI 均完成 312 帧，拖拽和缩放事件均改变了视口；保留区验证了 1,250,033,664 个原始
字节。固定池占用约 1.365 GB，快照持有过久会触发显式背压。一次性回看完整 5 秒仍会增加
绘制工作，65,536 点视口是主要目标；硬件采集设备的 DMA/驱动延迟不在该测试范围内。

## 使用

```cpp
modules::plot::WaveformBuffer buffer(modules::plot::WaveformBuffer::Config::dual125MS());
auto snapshot = buffer.snapshot();
plot.setSeries({{snapshot.channels[0]}, {snapshot.channels[1]}});
```

采集线程按 `channels * blockSamples` 字节提交完整交错块；`tryAppend()` 返回 `false` 时应暂停
或重试设备队列。不要在快照仍被渲染时强制回收它。

默认配置现为轻量配置，以上历史实测对应显式高速预设。新接入、16 位格式和分包适配见
[科学绘图应用开发](科学绘图应用开发.md)。
